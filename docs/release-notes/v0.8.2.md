## Release notes

Find stays responsive on very large files: a 28 MB log with 10,000 find results open now types, scrolls and re-searches without pauses.

### Performance

- **Find results list** — the Find Results panel is now a native table. With 10,000 results open on a 28 MB log, a keystroke costs about 1 ms instead of 12, moving the caret no longer re-evaluates the whole list, and results appear in the first frame after the search finishes (52 ms → 2 ms).
- **Re-search after edits** — the automatic refresh that runs 1.2 s after you stop typing no longer shows a spinner, writes to the Output panel or republishes unchanged results (editor highlights are still refreshed, so a typo fixed inside a match gets its highlight back); the longest main-thread pause it caused on the 28 MB log dropped from 228 ms to 12 ms, and the list keeps its scroll position. A search you start yourself still refreshes everything and scrolls the list to the top.
- **Search engine** — plain (non-regex, non-whole-word) queries made of ASCII characters use a direct chunked scan instead of the regular-expression engine: a search over 28 MB finishes in roughly half the time (301 ms → 157 ms including the result list). Case-insensitive matching for these queries folds only A–Z, so the Kelvin sign (K), long s (ſ) and ß↔ss no longer match an ASCII query; regular-expression and whole-word searches are unchanged.

### For contributors

- `scripts/bench.sh --only findui` runs the new end-to-end find benchmark on a generated 28 MB server log (results published, first frame, typing and caret movement with results open, re-search stall, scrolling and jumping to results), with controls without results and with the panel or scroll markers hidden. See `docs/performance.md`.
- `PerfProbe.measure` (HyperCore) and more `Perf.measure` probes report the index rebuild snapshot, fold/secret scan completions, list reloads and highlight updates under `--debug-perf`; they cost nothing otherwise.
- `AppModel.searchCompletionCount` increments after every search pass, including silent ones that publish nothing; the self-test and bench wait on it instead of `searchGeneration`.

### Compatibility

- macOS 15 (Sequoia) or later. The DMG (`HyperEdit-<version>-universal.dmg`) contains one universal binary that runs natively on Apple Silicon (arm64) and Intel (x86_64) Macs.
- No settings or files need migrating.
