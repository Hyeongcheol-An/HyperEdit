## Release notes

Files opened from Finder, the Dock or the command line now open as tabs in the HyperEdit window.

### Added

- **Open With, the Dock and `open -a`** — HyperEdit was already listed under **Open With** for plain-text and Markdown files, but nothing received the file. A file opened from Finder, dropped on the Dock icon or passed with `open -a HyperEdit notes.md` now opens as a tab in the one HyperEdit window. Several files at once get a tab each and the last one is shown; a file that is already open just switches to its tab, and the file you are viewing is not read again. Tabs from the last session stay where they are. A file reached under another spelling of its name (letter case, composed or decomposed Hangul) uses its one tab.
- **Files on the command line** — `HyperEdit a.md b.md` (the binary inside the app bundle) opens both as tabs. The files may stand anywhere among the options: `HyperEdit a.md --ephemeral b.md` opens both as well.
- **Things that cannot be opened** — a folder, a path that does not exist or a file that is not text is not opened and is reported in the Output panel. No empty file is created for a missing path.
- **While HyperEdit is busy** — if the app is locked, the files open after you unlock it, so nothing changes behind the lock screen. While a macro is playing or a sheet or dialog is open, they open when it is finished. While you are writing a note in the Quick Append panel, they open after the note is appended or the panel is closed, so ⌘↩ cannot land in the wrong file; an empty Quick Append panel does not hold a file back.

### Fixed

- Until now, opening a file from Finder or the Dock while HyperEdit was running did not open the file and added a second window showing the same document. There is one window again.

### Known limitations

- HyperEdit does not bring itself to the front: Finder, the Dock and `open` do that, and `open -g` keeps it in the background on purpose. A minimized window is brought back.
- A file that is not text is refused when it is handed over from outside; it is not passed on to its default app, as it is when you pick it with ⌘O or in the sidebar.
- If the editor window has been closed while the Settings window is still open, a file opened from outside brings the editor window back with that file, but its tab bar may not be updated: it can still show the tabs it had when it was closed.

### For contributors

- `ExternalOpen` collects requests from `application(_:open:)` (Finder, the Dock, `open -a`) and hands them to `AppModel.openExternal` once the document may change. The window group no longer creates windows for external events (`.handlesExternalEvents(matching: [])`): SwiftUI added one per open event, on the same model.
- Files on the command line are picked out by the app itself (`LaunchOptions.parse`), not taken from `application(_:openFiles:)`: AppKit pairs every dash argument with the argument after it, so it handed over the *values* of this app's options as files and swallowed a file that followed an option without a value (`--quit a.md`). Options that take a value are listed in `LaunchOptions.valueOptions` (`optionalValues` for `--split`); `LaunchOptions.value(_:)` answers only for those, so a new option that is missing from the list does not work at all instead of having its value opened as a file.
- **Automated runs are isolated in one place**, `Apps/mac/AutomationRun.swift`. A test build shares its bundle identifier with the installed app, so everything macOS keeps per bundle identifier, and everything it routes by it, is shared too.
  - `isIsolated` (a scripted run or `--ephemeral`) keeps away from the user's preferences, default folder, snapshots, bookmarks, snippets, macros, grammars, saved window state and — new — saved window frames. SwiftUI saves the frame of its window by name whenever the window becomes key, which neither `restorationBehavior(.disabled)` nor `ApplePersistenceIgnoreState` stops; a background self-test changed where the installed app's window opens. Isolated runs replace the `NSWindow` methods that save or read a frame by name before any window exists.
  - `isScripted` (`--selftest`, `--selftest-open`, `--bench`, `--realuse`, `--snapshot`, and the launch-timing flags) additionally steps back whenever macOS activates the run — the harness too, at any time during the run, not only at launch — shows its Quick Append panel behind the other windows without taking keys, does not register the global shortcut with the system (`GlobalHotKey.press` plays a press instead), and opens a file handed over from outside only when it is one of its own fixtures (`ExternalOpen.mayOpen`): inside a folder directly in the temporary folder whose name starts with `hyperedit-`, or directly in the folder of the `--file` document. Anything else is refused with `[automation] not opened — outside this run's folders: <path>` in the Output panel and on stderr — a file you open in Finder while a test is running can reach the test instance, and its next edit would be autosaved into your file. Name the fixture folders of new tests `hyperedit-…`.
  - A `--snapshot` run without `--snapshot-activate` therefore captures the window, and a `--quick-append` panel, in their inactive look.
  - Checks: the self-test's `isolation:` lines and the harness scenario `automation-isolated` share one probe (`IsolationProbe`).
- Tests do not send Apple events to the app itself: an open-documents or reopen event to one's own process can activate the app (two times out of three), and `NSApp.deactivate()` did not take it back. `open-external` calls the delegate directly. `open-launch` is launched once more by `scripts/realuse.sh`, with two text files, a folder and a missing path as bare arguments right after `--quit`, and reports into `<out>/open-launch/` (`scripts/realuse.sh --only open-launch`; add `-- --locked` for the launch lock). The script now stops the app it launched when it is interrupted, and lists the files a run refused after the report.

### Compatibility

- macOS 15 (Sequoia) or later. The DMG (`HyperEdit-<version>-universal.dmg`) contains one universal binary that runs natively on Apple Silicon (arm64) and Intel (x86_64) Macs.
- No settings or files need migrating.
