## Release notes

⌘↓ reaches the end of the document again after a fold that covers the end has opened.

### Fixed

- **⌘↓ into a fold that reaches the end of the document** — with ⌘↓ from the header of such a fold, the fold opened and the caret went to the end, but in documents of short lines the view could stay at the top; the same happened with ⌘↓ right after unfolding such a region. The view now goes to the end.

### For contributors

- After a fold that reaches the end of the document has opened, the fragment of the last paragraph is still where it was while folded, right below the header: the paragraphs in between were never enumerated, and TextKit 2 keeps it there until it revises its height estimate. AppKit then takes the end of the document for visible and does not scroll. `HyperTextView.revealDocumentEndIfMissed` checks against the laid-out viewport, not against coordinates, and pins the view to the end. It only shows when the estimate already matches the text, so it depends on what was scrolled before: the full harness run failed every time, the scenario alone never did (`--only scroll-knob-state,fold-giant` shows it on the old code).

### Compatibility

- macOS 15 (Sequoia) or later. The DMG (`HyperEdit-<version>-universal.dmg`) contains one universal binary that runs natively on Apple Silicon (arm64) and Intel (x86_64) Macs.
