## Release notes

Undo and redo of a tool that rewrites a large range — Toggle Comment, Format JSON, Align Columns, the line and selection tools — no longer take seconds.

### Fixed

- **Undo after a whole-document tool** — undoing Toggle Comment on every line of a 1.3 MB document took 5.3 s, redoing it another 5.3 s, and undoing Format JSON on 1.7 MB 0.85 s. They now take 0.26 s, 0.26 s and 0.21 s. The tools themselves were fast already (about 0.3 s and 0.15 s).
- **⌘↑ after undoing a large edit** — the first line could sit at the very top edge of the window with the padding above it cut off. Going to the start of the document always shows the padding.

### Changed

- After such a tool on a large range the view stays where it was instead of moving to the end of the changed text, and undo brings back the selection you had before the tool.
- After an undo that leaves a very long selection — the whole document, for instance — the view stays where it is when it already shows part of that selection; until now the editor laid the whole selection out to bring it into view (7.5 s for a 1.3 MB document).

### Known limitations

- A range below 16,384 UTF-16 units still goes the typing way, and so does a large edit that is not one of these tools: ⌘Z after Select All and typing over the selection is AppKit's typing undo, and the more text it has to put back, the longer it takes.

### For contributors

- The tools put their result in with `insertText`, so AppKit registered a typing undo that puts the removed text back as an attributed string. Inserting its attribute runs into the storage's run array costs (runs inserted × runs after them): nearly all of the 5 s was `memmove` in `NSMutableRLEArray`. `HyperTextView.replaceForTool` sends a range of `toolBatchLength` (16,384 UTF-16 units) or more through `performReplacements`, which registers its own undo and swaps plain characters in one batch edit — the path Replace All already used. Smaller ranges keep the typing path and its behaviour.
- `typing-big-tools-redo` now judges the undo and the redo as well, checks that the selection from before the tool is back, and measures an undo just below the threshold. The undo of 12,000 characters at the start of the 1.3 MB document on the typing path takes 60–72 ms.
- After an undo the editor reveals the selection the undo left. A selection of `longRevealLength` or more is not handed to `scrollRangeToVisible` whole (`undoDidChange`, `revealCaretAfterRelayout`): AppKit lays out the entire range to find its rectangle. The view is left alone when the selection is the whole document or the view is already inside it; otherwise only the start of the range is revealed.
- AppKit stops scrolling as soon as the box of the first line is on screen, so a reveal of the start of the document that comes up from text not laid out yet left the 12 pt of padding above the first line cut off; `revealTopInsetWithDocumentStart` scrolls on to the top. The tools used to hide this by moving the view to the end of the text first. `typing-big-tools` checks the top after ⌘↑ and after a tool used at the top.

### Compatibility

- macOS 15 (Sequoia) or later. The DMG (`HyperEdit-<version>-universal.dmg`) contains one universal binary that runs natively on Apple Silicon (arm64) and Intel (x86_64) Macs.
